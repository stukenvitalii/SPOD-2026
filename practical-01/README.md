# Практическая работа № 1

## Задание и реализация

Все процессы, кроме нулевого, отправляют ему свой ранг. Только процесс `0` печатает сообщения: сначала собственный ранг, затем ранг после каждого приёма.

`src/unordered.cpp` принимает с `MPI_ANY_SOURCE`. Остальные ранги выводятся в порядке фактического приёма; этот порядок может меняться между запусками, но не обязан меняться каждый раз.

`src/ordered.cpp` принимает последовательно от источников `1, 2, …, p − 1`. Поэтому вывод всегда упорядочен. Отправители не обязаны выполнять отправки в этом порядке.

Обе программы используют `MPI_Comm_size`, обрабатывают `p − 1` сообщений за раунд и работают при одном процессе: в обычном режиме он печатает только `Hello from 0`. Общие параметры и функции находятся в `src/common.hpp`.

[Сети Петри для обеих версий](diagrams/README.md) сохранены в PNG и SVG; там же приведены начальная маркировка, объяснение переходов и результаты проверки моделей.

## Сборка и запуск

Команды выполняются из корня проекта:

```powershell
.\practical-01\build.ps1
.\practical-01\run.ps1 -Mode unordered -Processes 8
.\practical-01\run.ps1 -Mode ordered -Processes 8
```

Сборка: C++17, `-O2`, предупреждения `-Wall -Wextra -Wpedantic`. Запускать `mpiexec` нужно из обычного Windows PowerShell, а не через MSYS bash.

Один возможный результат первой версии:

```text
Hello from 0
Hello from 2
Hello from 1
Hello from 3
```

Для второй версии при четырёх процессах результат всегда:

```text
Hello from 0
Hello from 1
Hello from 2
Hello from 3
```

Повторные запуски:

```powershell
1..5 | ForEach-Object {
    .\practical-01\run.ps1 -Mode unordered -Processes 8
    Write-Host ''
}
```

Несколько раундов в одном запуске:

```powershell
.\practical-01\run.ps1 -Mode unordered -Processes 8 -Rounds 3
```

В каждом раунде каждый отправитель посылает один пакет. Тег MPI равен номеру раунда: сообщения следующих раундов не могут подменить сообщения текущего.

## Измерения

Для демонстрации используются обычные запуски. Для измерений — отдельный режим без печати приветствий:

```powershell
.\practical-01\run.ps1 -Mode unordered -Processes 8 -Rounds 1000 -Count 256 -Benchmark
.\practical-01\run.ps1 -Mode ordered -Processes 8 -Rounds 1000 -Count 256 -Benchmark
```

`Count` задаёт число элементов `MPI_INT` в одном сообщении. По умолчанию передаётся один ранг. При `Count > 1` сообщение заполняется копиями ранга: это экспериментальное увеличение объёма данных, а не дополнительное требование задания. В текущей сборке один элемент занимает 4 байта.

Перед измерением выполняется барьер, затем каждый процесс замеряет свой интервал через `MPI_Wtime`. В конце `MPI_Reduce` выбирает максимальный интервал. Выделение памяти, подготовка сообщений, начальный барьер, финальная редукция, запуск процессов и печать CSV не входят в измеряемое время.

CSV-строка содержит:

```text
mode,processes,count,rounds,total_seconds,seconds_per_round
```

`seconds_per_round` — среднее время раунда в серии обменов. Между раундами нет барьера, поэтому серии допускают перекрытие работы участников. Это не отдельный замер задержки каждого сообщения. Результаты режима без вывода не включают стоимость печати обычной демонстрационной программы.

Сбор таблицы для обеих версий:

```powershell
.\practical-01\benchmark.ps1
```

По умолчанию: `1, 2, 4, 8, 16` процессов; `1, 256, 16384` элементов; 1000 раундов; три повторения каждой комбинации. Перед каждой серией выполняется короткий прогрев отдельным запуском. CSV сохраняется в `practical-01/results/`.

Короткий эксперимент:

```powershell
.\practical-01\benchmark.ps1 -Processes 1,2,4,8 -Counts 1,256 -Rounds 100 -Repeats 2
```

Для графиков удобно использовать Excel: по X — процессы, по Y — время раунда, отдельные кривые — размеры сообщения; версии алгоритма сравниваются между собой. Сохраните параметры компьютера, число физических ядер и логических процессоров, параметры сборки и условия запуска. Избегайте другой тяжёлой нагрузки во время измерений.

При `p = 1` обмен отсутствует. Время этого случая нельзя содержательно использовать как последовательное решение той же коммуникационной нагрузки и ожидать обычного ускорения `T1/Tp`. Увеличение числа процессов здесь также увеличивает число сообщений. В отчёте нужно явно объяснить это ограничение и сверить применение общего требования о графиках ускорения с методичкой преподавателя. Замедление в этой работе допустимо.

## Проверка

```powershell
.\practical-01\check.ps1
```

Скрипт проверяет обе версии на `1, 2, 4, 8, 16` процессах по три раунда: количество строк, нулевой ранг первым, отсутствие пропущенных и повторных рангов, строгий порядок второй версии. Отдельно проверяет режим измерения с сообщениями по 64 КиБ.

## Типичные проблемы

- `MPI headers not found`: выполнить `.\scripts\setup.ps1`.
- `Microsoft MPI is not installed`: выполнить установку через `setup.ps1`.
- Нет `.exe`: выполнить `build.ps1`.
- Не найдена DLL GCC: добавить каталог своего UCRT64-компилятора в `PATH`. При стандартной установке это делает `run.ps1`.
- Если Windows показывает запрос брандмауэра при первом запуске, учитывайте выбранную сеть; для локальной работы публичный сетевой доступ не нужен.

Если процесс аварийно завершился, `mpiexec` может напечатать несколько диагностических строк от разных участников. Скрипт запуска возвращает ошибку; не использовать такой запуск как результат измерения.

## macOS

Код C++ не использует Windows API. На Mac требуется собрать его заново с Open MPI; готовые Windows `.exe` и папка `.tools/msmpi` для этого не используются. Подход одинаковый для Apple Silicon и Intel при поддержке установленной версии macOS пакетным менеджером.

Если средства разработки Apple ещё не установлены:

```bash
xcode-select --install
```

Установить [Homebrew](https://brew.sh/), если его нет, затем выполнить в Terminal:

```bash
brew install open-mpi
```

После копирования проекта на Mac выполнить из его корня:

```bash
bash practical-01/build.sh
bash practical-01/run.sh unordered 4
bash practical-01/run.sh ordered 4
```

`build.sh` использует обёртку `mpic++`: она сама задаёт пути к заголовкам и библиотекам установленного MPI. Бинарные файлы без расширения создаются в `practical-01/build/`. Скрипты вызываются через `bash`, поэтому менять права через `chmod` не требуется.

Параметры программы передаются после числа процессов:

```bash
bash practical-01/run.sh unordered 8 --rounds 3
bash practical-01/run.sh ordered 8 --rounds 1000 --count 256 --benchmark
```

Если Open MPI сообщает, что доступных slots недостаточно, явно разрешить запуск большего числа процессов:

```bash
OVERSUBSCRIBE=1 bash practical-01/run.sh ordered 16
```

Замеры для двух версий, с теми же наборами параметров, что в PowerShell-скрипте:

```bash
OVERSUBSCRIBE=1 bash practical-01/benchmark.sh
```

При необходимости сократить серию:

```bash
ROUNDS=100 REPEATS=2 OVERSUBSCRIBE=1 bash practical-01/benchmark.sh
```

Режим oversubscribe влияет на время: отметьте его использование в отчёте. Не объединяйте замеры Windows и Mac в одну зависимость как результаты одного компьютера — отличаются оборудование, ОС и реализация MPI.

На Windows проверены сборка и выполнение C++-программ. Проверка исполнения на настоящем Mac пока не проведена.

Документация: [Open MPI: установка на macOS](https://docs.open-mpi.org/en/main/installing-open-mpi/quickstart.html), [Homebrew: open-mpi](https://formulae.brew.sh/formula/open-mpi), [параметры mpirun](https://docs.open-mpi.org/en/main/man-openmpi/man1/mpirun.1.html).
